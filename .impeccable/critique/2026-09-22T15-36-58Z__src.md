## Design Specificity Verdict

Strongly product-specific, operationally incomplete. Kinship & Hearth, two-speed contribution, provenance, care, grief-aware reactions, and preservation ceremony are genuinely authored. The central defect is false-affordance debt: polished controls are often placeholders, damaging trust more than visibly unfinished UI.

Static detector: exact JSON [], 0 findings. Browser evidence across Hearth, Chat, Care, Archive and Kinship at 393×852 found no page overflow and representative contrast passed. Systemic leads: many visually compact 22–40px controls rely on hitSlop; no semantic headings/landmarks in React Native Web. Runtime overlay found 10 occurrences, predominantly RN Web raster/clipping false positives; one padding transition is a performance lead. No persistent overlay remains.

## Overall Impression

The app is emotionally intelligent and visually coherent. The next level is not prettier styling: every visible promise must become real, and recurring workflows must scale beyond fixture-sized families.

## Strengths

1. Everyday utility and permanent preservation are clearly separated and connected.
2. Sensitive moments receive unusually humane semantics and defaults.
3. Contribution forms respect imperfect memory and preserve work on failure.
4. The visual system consistently communicates warmth, privacy and permanence.
5. The save confirmation is an authored emotional peak.

## Cognitive Load

Failures: Hearth module density; Archive combining five destinations; long forms exposing optional metadata; unbounded person selectors; recurring explanatory copy that cannot collapse. >4-option points include six memory kinds, five Archive categories, care candidates, unbounded people, deed tags, and story-card reactions/comments.

## Emotional Journey

Sign-in establishes trust but unsupported OAuth disappoints. Onboarding begins clearly then fails at invitation validation. Hearth is warm and increasingly useful. Contribution and grief-sensitive flows are strongest. Care's inert controls create the most dangerous rupture. Archive is emotionally specific but overloaded. Story detail reads beautifully but can lose failed comments.

## Priority Improvements

### P0 — Invitation onboarding is not a real joining flow
Onboarding accepts any nonempty code; Settings derives a placeholder code instead of using secure server invitations. Connect the server endpoint, deep links, family/inviter confirmation, and malformed/expired/used/revoked/offline states. Suggested: /impeccable harden onboarding and invitations.

### P0 — Voice is presented as primary but remains simulated
Chat hold-to-talk, Add Great Deed voice, and Archive voice controls do not record. Implement permission, duration, cancel, lock/tap alternative, review, re-record, upload, unsent recovery and transcription, or remove enabled controls. Suggested: /impeccable harden voice contribution.

### P1 — Enabled placeholders appear throughout Care, Archive, Settings and Sign-in
Remove normal enabled controls that only do nothing or announce Coming soon. Complete loading/error/success behavior for what remains. Suggested: /impeccable harden entire app.

### P1 — Audience controls do not match the promised privacy model
Add Memory exposes only everyone/adults and Add Great Deed hardcodes everyone. Build a reusable selector with recipient preview, safe defaults, care/branch options and child restrictions. Suggested: /impeccable shape audience controls.

### P1 — Failed comments can erase family words
Keep drafts until confirmation; show pending/failed comment state with Retry/Edit/Discard. Suggested: /impeccable harden story comments.

### P1 — Native shell is light-only and phone-shaped
Add semantic light/dark/high-contrast schemes and compact/medium/expanded navigation, including Android rail/drawer. Suggested: /impeccable colorize dark theme and /impeccable adapt native shell.

### P2 — Person selection does not scale
Build a shared searchable picker with recents, relationship context, selected summary and Add someone new. Suggested: /impeccable distill family pickers.

### P2 — Archive should become navigation, not one enormous screen
Create a visible preservation dashboard and push Recipe, Letters, Voices, Objects and Who Is This into focused stack screens. Suggested: /impeccable shape Archive navigation.

### P2 — Profiles dead-end and use outdated Great Deeds terminology
Add a preselected “Share a memory about…” action, kind-aware counts and remembrance-specific CTA. Suggested: /impeccable onboard profiles and /impeccable clarify story terminology.

### P2 — Touch and semantic structure need a systemic pass
Correct shared Chip/SectionHeader/ReactionBar/VoiceNote/thread controls to stable 44/48-point wrappers and add web headings/landmarks/focus structure. Suggested: /impeccable audit accessibility.
